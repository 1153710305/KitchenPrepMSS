# 后厨备菜管理和统计系统 (V2.5.0)

本项目是一个专门针对校园、机关或大中型食堂后厨设计的“日矩阵记账、深度财务统计及 AI 膳食配餐辅助决策”全功能管理系统。它完全采用 **TypeScript + React + Express Full-Stack** 架构设计，保障流畅的人机交互以及高密度的操作性能。

## 🌟 核心功能特色

1. **多级表格人群管理（级联决策根）**：
   - 包含以 **教师备餐**、**幼儿备餐**、**低年级备餐** 和 **高年级备餐** 等组成的独立核算客群。

2. **多维食材大类管理（记账大品类）**：
   - 可在 **蔬菜**、**粮油**、**调料**、**肉类**、**低耗品**、**水果** 等品类间动态抉择。
   - 特设 **合计汇总表**：一键生成全类别当期资金统计、各品类采购总金额比例及详细耗资说明。

3. **双重高性能编辑视图**：
   - **EXCEL 日历总矩阵**：复现经典的日历横轴大宽表，横向是 1号 到 31号 (根据月度自适应天数)，纵向是细分食材（例如：土豆、柿子、大黄油等）。每天下方含有 **数量**、**单价**、**金额** 纵队（金额由公式 `数量 * 单价` 自适应动态生成），首列冻结，支持批量一整列克隆单价调价。
   - **单日聚焦卡片（推荐模式）**：专为非宽屏或高频录入人员设计。支持在横向日期轴上点击指定天（如 15日），无需横向拖曳即可在垂直卡片内微调当天所有菜品的数量与价格，带来极佳的用户体验。

4. **实时财务图表看板**：
   - 引入 **Recharts** 绘制日消耗开支平滑面积图，辅助控制超预算。
   - 精细渲染食材大类采购资金配比条状占比，清晰揭示成本结构。
   - 显示全月度总开销、品类覆盖密度、日均耗资、以及 **重点监控高开销食材 Top 5 榜单**。

5. **AI 智能营养调配与控本审计**：
   - 在服务端深层整合 **Gemini-3.5-flash** 与 `@google/genai` 统一接口。
   - 默认提供 **在线打字流式 (Chunk-by-Chunk SSE Stream)** 与 **传统常规普通 API** 双重模式，一键切换。
   - 提取当期采购高频项目轻量级序列化传递给 AI，由专业食堂膳食调配师与财务管控专家多维度反馈“膳食平衡与人群营养诊断”、“后厨控本替代路径”和“采购冷链储存安全指导”，并给出膳食健康指数。

6. **行政管理与控制配置后台 (Diagnostics Admin)**：
   - 具备功能强大的受众人群一级分类、食材分类二级品类的添加、更新、删除即时数据级联核对 (CRUD) 面板。
   - 搭载进程总线实时嗅探和日志审计器，开发人员和行政管理人员可在此处单一入口对后厨系统、安全及离线缓存进行全量诊断。

7. **离线备份与迁移**：
   - 支持全账目一键打包导出为本地 `.json` 数据备份包，并配置了安全性的校验导入功能，实现零流失记账。
   - 每张单大类表支持一键一键导出为 Excel 可直接识别的 UTF-8-BOM 开源 CSV 总格。

---

## 🛠️ 技术底盘与软件架构

- **前端技术**：React (V19) + TypeScript + Tailwind CSS (V4) + lucide-react (图标)
- **绘图引擎**：Recharts
- **富文本解释**：React-Markdown (用于渲染 AI 的结构化深度分析)
- **后端服务**：Node.js + Express (统一端口 3000 ，容器入口防沙箱过滤)
- **编译工具**：Vite + esbuild (将 Express 静态集成编译至单个 cjs 自立服务，契合前后端完美分离的趋势需求)

### [V1.3.1] - 2026-06-23 (核心响应性 Bug 修复)
- **底层不可变数据(Immutable)更新机制升级**：
  - **现象定位**：修复了用户在“Excel日历总矩阵”和“单日聚焦卡片”中无法修改食材数量与单价，以及“点击新增项没有反应”的严重系统响应性阻滞缺陷。
  - **根源剖析**：由于之前底层 `PrepReportService` 状态服务采用的是 Mutable（可变突变）形式的深层级对象属性修改（如直接 `report.items.push()` 或直接修改深层 `dailyData[day]` 指标），且修改单元格处省去了分发广播事件，导致 React 内存引用没有产生变化，进而触发不了 UI 依赖项的 `useMemo` 重新计算及受控组件值的有效回刷。
  - **重构方案**：对 `addPreparedItem`、`updateCell`、`deletePreparedItem`、`batchUpdatePriceCol` 以及 `clearAllMonthlyCells` 等全部涉及多维底册突变更改的方法进行深度重构，完全转向不可变(Immutable)对象及数组克隆模型。每当用户产生单个数字击键、单价一键同步或新增菜品行为，均会创建全新引用结构的 reports、report 树并全速持久化分发给监听器，完美驱动 React 高灵敏重绘刷新，使得输入编辑与新增操作即时生效、毫无卡顿！

## 🚀 系统部署及数据安全手册

由于本项目主要服务于教育单位，保密级别高、且数据绝对安全性是首要原则。系统经过专门架构设计，既支持托管在腾讯云（使用私有对象存储隔离数据），也支持在一台学校本地的普通 PC 电脑上单机运行。

### 一、 本地单机部署方案（适合独立电脑运行，数据完全保密）

本地部署旨在让学校后厨管理人员或库管在自己电脑上单机操作，数据全部保存在本地硬盘的 `data/db.json` 中，不受浏览器缓存清理或网络断网的影响。

#### 1. 运行环境准备
- 在部署的电脑上下载并安装 **Node.js**（推荐选择最新 LTS 版本，下载地址：[Node.js 官方网站](https://nodejs.org/)）。

#### 2. 程序部署步骤
1. 将本项目源码文件夹复制到目标电脑的某个非系统盘目录下（例如 `D:\KitchenPrepMSS`）。
2. 在该目录下，使用管理员权限打开命令行（CMD 或 PowerShell），执行以下命令安装依赖：
   ```bash
   npm install
   ```
3. 在根目录创建或编辑 `.env` 配置文件，确保包含以下配置项：
   ```env
   # 首页登录密码与管理密码
   VITE_LOGIN_PASSWORD="guest"
   VITE_ADMIN_PASSWORD="admin"

   # 启用本地数据存储
   STORAGE_TYPE="local"
   LOCAL_DB_PATH="data/db.json"
   ```
4. 执行编译命令，生成静态生产文件包：
   ```bash
   npm run build
   ```

#### 3. 制作“一键双击启动”脚本（防非技术人员误操作）
为了方便学校工作人员每日开箱即用，避免输入命令，可在项目根目录下新建一个名为 `双击启动系统.bat` 的文本文件，并将以下内容复制进去保存：
```bat
@echo off
:: 设置字符集为 UTF-8 防乱码
chcp 65001 > nul
title 后厨备餐与台账管理系统

echo ===================================================
echo   后厨备餐管理与统计系统正在启动中...
echo   说明：启动成功后会自动打开浏览器，请勿关闭本命令行窗口！
echo ===================================================

:: 延迟 2 秒自动呼起默认浏览器访问系统
start http://localhost:3000

:: 运行 Express 服务端
npm run dev

pause
```
之后，操作人员只需双击 `双击启动系统.bat`，即可自动启动系统并弹出浏览器页面开始使用。

#### 4. 本地数据安全与快照恢复策略
- **本地主数据文件**：保存在 `data/db.json` 中。
- **自动备份防误删**：当每次修改账目或出入库记录失去焦点保存时，系统除了更新 `data/db.json` 之外，还会在 `data/backups/` 目录下自动生成一个带有精确时间戳的快照文件，形如：`db_20260630-162000.json`。
- **超期清理**：为了防止备份膨胀，后端会自动将备份快照控制在最近 30 次，超出 30 个的历史老备份会被自动轮换清除。
- **数据恢复方案**：如果不小心在管理配置后台中误清空了账目，或者修改错误想要找回，可以直接在本地 `data/backups/` 下找到历史某时刻的快照，将其更名复制替换掉 `data/db.json` 即可完成完全恢复，或者通过管理配置后台的快照回滚功能一键物理回滚。

### 二、 腾讯云端部署方案（使用腾讯云服务器 + COS 对象存储）

若教育单位有多个校区需要联网协同录入，或希望数据存放在云端且定期异地冷备，可将系统部署至腾讯云。

#### 1. 腾讯云 COS 对象存储准备
1. 登录腾讯云控制台，进入 **对象存储 (COS)** 控制台。
2. 新建一个存储桶（Bucket），如命名为 `kitchen-prep-1234567890`，所属地域选择就近地域（如 `ap-guangzhou`）。
3. 访问权限务必设置为 **私有读写**（因包含财务和就餐人数敏感信息，绝对不能公开）。
4. 在腾讯云访问管理（CAM）控制台，获取该账号的 `SecretId` 和 `SecretKey`。
5. **重要安全建议**：在存储桶的安全设置中开启 **版本控制（Versioning）**。开启后，即使代码或人为误删了 COS 中的 `db.json`，COS 也会保留其所有历史覆盖版本，可在腾讯云后台随时拉回，确保数据资产绝对安全。

#### 2. 云端服务器配置
1. 购买一台腾讯云轻量应用服务器（或云服务器 CVM），系统选择 **Ubuntu/CentOS**。
2. 在服务器上安装 **Node.js** 和 **PM2** 守护工具：
   ```bash
   # 安装 Node.js (以 Ubuntu 为例)
   curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   sudo apt-get install -y nodejs
   # 全局安装 pm2 进程守护管理器
   sudo npm install pm2 -g
   ```
3. 上传项目源码至服务器，并在项目根目录下执行 `npm install`。
4. 创建项目 `.env` 配置文件，填入对应的云端配置：
   ```env
   # 首页登录密码及管理密码
   VITE_LOGIN_PASSWORD="your_strong_login_password"
   VITE_ADMIN_PASSWORD="your_strong_admin_password"

   # 切换为腾讯云 COS 对象存储存储形态
   STORAGE_TYPE="cos"
   COS_SECRET_ID="你的腾讯云SecretId"
   COS_SECRET_KEY="你的腾讯云SecretKey"
   COS_REGION="ap-guangzhou"
   COS_BUCKET="kitchen-prep-1234567890"
   COS_KEY="production/db.json"
   ```
5. 编译代码：
   ```bash
   npm run build
   ```

#### 3. 云端生产环境启动与守护
云服务器中应使用 pm2 进行守护启动，以防服务器断网重启或异常中断导致服务无法访问：
```bash
# 启动 Express 生产独立编译包并命名为 kitchen-prep-system
pm2 start dist/server.cjs --name "kitchen-prep-system"

# 设置开机自启
pm2 save
pm2 startup
```
若需要配置域名访问，请使用 Nginx 监听 80/443 端口，并通过反向代理反代至服务器本地的 `http://127.0.0.1:3000` 即可。
